### 1. ترتيب تطبيق ملفات الهجرة

يجب تطبيق ملفات الهجرة بالترتيب الزمني الدقيق التالي عبر Supabase CLI أو واجهة SQL Editor:

```bash
# 1. الجلسة A: قفل الدوال الحساسة وإنشاء قفل التهيئة الأحادية
supabase db execute -f supabase/migrations/20261017130000_lockdown_privileged_functions_and_bootstrap.sql

# 2. الجلسة B: جداول تحصين البوت ومحاولات التحقق الفعلي بالبريد
supabase db execute -f supabase/migrations/20261017140000_telegram_bot_hardening_and_email_verification.sql

# 3. الجلسة C: تفويض الأقسام وسجل الأكواد التراكمي وتأمين RLS
supabase db execute -f supabase/migrations/20261017150000_approval_delegation_code_registry_and_rls.sql
```

> **تنبيه خاص بجداول الأعمال:**
> تم وضع المقترح الخاص بتقييد جداول المستودع والمشتريات التشغيلية بحالة الحساب النشط في مجلد منفصل:
> `supabase/pending/20261017153000_enforce_active_status_on_business_tables.sql`
> راجع هذا الملف مع فريق التشغيل قبل تطبيقه للتأكد من عدم حجب أي عمليات قديمة.

### 2. نشر الدوال السحابية وأسرار البيئة

#### أ) تعيين الأسرار في Supabase Secrets:
يجب ضبط القيم السرية التالية وعدم تخزينها في كود العميل:
```bash
supabase secrets set \
  TELEGRAM_BOT_TOKEN="your_bot_token_from_botfather" \
  TELEGRAM_WEBHOOK_SECRET="generate_a_random_32_char_secret" \
  RESEND_API_KEY="re_xxxxxxxxxxxxxxxxxxxx" \
  RESEND_FROM_EMAIL="Warehouse Ledger <onboarding@yourdomain.com>" \
  OTP_PEPPER="generate_a_random_sha256_pepper_secret" \
  BOOTSTRAP_ADMIN_EMAIL="marwandesouqhi@gmail.com" \
  BOOTSTRAP_ADMIN_USERNAME="marwan-desouky"
```

#### ب) نشر الدوال السحابية:
```bash
supabase functions deploy admin-users
supabase functions deploy telegram-bot --no-verify-jwt
supabase functions deploy verify-email
supabase functions deploy login-bridge --no-verify-jwt
```

#### ج) ربط Webhook بوت تيليجرام:
قم بتوجيه البوت للرابط المشفر مع رأس الأمان السري:
```bash
curl -F "url=https://<project-ref>.supabase.co/functions/v1/telegram-bot" \
     -F "secret_token=<YOUR_TELEGRAM_WEBHOOK_SECRET>" \
     https://api.telegram.org/bot<YOUR_BOT_TOKEN>/setWebhook
```

### 3. خطوات الفحص العملي خطوة بخطوة

#### الخطوة 1: التهيئة الأحادية لمدير النظام (Bootstrap)
- [ ] ادخل إلى شاشة تسجيل الدخول وأنشئ أو أكد حساب بريدك الإلكتروني `marwandesouqhi@gmail.com` في Supabase Auth.
- [ ] استدع إجراء `bootstrap_system_admin` عبر جلسة المالك الموثقة.
- [ ] تحقق من استجابة النظام بنجاح وتخصيص الكود `SYS-ADM-000001` وحالة `active`.
- [ ] كرر المحاولة للتحقق من قفل التهيئة الأحادية (`system_bootstrap_state`): يجب أن يرفض النظام إعادة التهيئة بحالة خطأ صريحة.
- [ ] حاول استدعاء التهيئة من حساب مستخدم آخر غير المالك: يجب أن يتم الرفض فوراً وتسجيل محاولة غير مصرح بها في `audit_logs`.

#### الخطوة 2: تجربة التسجيل عبر تيليجرام ورمز التحقق (Email OTP)
- [ ] افتح بوت تيليجرام وأرسل الأمر `/start`.
- [ ] تأكد من ظهور رسالة الترحيب الدقيقة وزر "بدء التسجيل (تسجيل موظف جديد)".
- [ ] ابدأ التسجيل وأدخل: الاسم، القسم، الدور المطلوب، والبريد الإلكتروني.
- [ ] **فحص أمني هام:** تأكد أن رد البوت لا يحتوي نهائياً على رمز التحقق، وإنما يطلب فحص صندوق البريد الوارد.
- [ ] افتح البريد الإلكتروني وتأكد من استلام رسالة OTP رسمية صادرة من Resend مكونة من 6 أرقام.
- [ ] حاول إدخال 5 رموز عشوائية خاطئة عبر الأمر `/verify 000000`: تأكد من تفعيل القفل الذري (Lockout) ورفض أي محاولة لاحقة لحماية الحساب من هجمات التخمين.
- [ ] في طلب تجريبي آخر، أدخل الرمز الصحيح وتأكد من تحول حالة التحقق إلى `verified`.

#### الخطوة 3: اعتماد الطلبات وتخصيص الأكواد الفريدة
- [ ] سجل الدخول بحساب مدير النظام وافتح صفحة "المستخدمون وسجل الموظفين".
- [ ] اضغط على تبويب "طلبات التسجيل (تيليجرام)".
- [ ] تحقق من أن الرموز المشفرة وHash الداخلي للبريد لا تظهر في الواجهة (تستخدم العرض الآمن `registration_requests_admin_view`).
- [ ] اضغط "اعتماد" لأحد الموظفين المؤكدين.
- [ ] تأكد من إنشاء وتخصيص الكود الوظيفي بالصيغة القياسية:
  - المخازن: `EMP-WRH-000001` وما بعده.
  - المشتريات: `EMP-PUR-000001` وما بعده.
- [ ] تحقق من إرسال رسالة تيليجرام للموظف تخبره بالاعتماد وتزوده برقمه الوظيفي.
- [ ] تأكد من تسجيل الكود في جدول `employee_code_registry` ومنع تكراره نهائياً.

#### الخطوة 4: اختبار تفويض الأقسام وعزل الصلاحيات (Delegation Matrix)
- [ ] في تبويب طلبات التسجيل، تأكد من وجود مفتاح "تفويض اعتماد طلبات الأقسام لمدراء الأقسام".
- [ ] عندما يكون التفويض **معطلاً** (الوضع الافتراضي):
  - ادخل بحساب مدير قسم مخازن: يجب ألا يتمكن من اعتماد أي طلب تسجيل.
- [ ] قم **بتفعيل** التفويض عبر حساب مدير النظام الرئيسي:
  - مدير قسم المخازن يستطيع الآن اعتماد موظفي قسم "المخازن" فقط.
  - مدير قسم المخازن يُمنع تلقائياً من اعتماد موظفي قسم "المشتريات".
  - مدير قسم المخازن يُمنع منعاً باتاً من ترقية أي شخص إلى دور `admin` أو `system_admin`.
  - المراجع يُمنع نهائياً من اعتماد طلبه الذاتي (Self-approval prevention).

#### الخطوة 5: تسجيل الدخول عبر جسر التوثيق الموحد (Login Bridge)
- [ ] افتح شاشة تسجيل الدخول وجرب تسجيل الدخول باستخدام:
  1. **اسم المستخدم:** مثل `ahmed_warehouse`.
  2. **الرقم الوظيفي الفريد:** مثل `EMP-WRH-000001`.
  3. **البريد الإلكتروني:** مثل `ahmed@example.com`.
- [ ] جرب إدخال كلمة مرور خاطئة: تأكد من إرجاع رسالة الخطأ العامة:
  `اسم المستخدم / المعرّف أو كلمة المرور غير صحيحة، أو الحساب غير نشط.`
  دون توضيح ما إذا كان المعرف موجوداً أم لا لمنع استنباط المستخدمين.
- [ ] جرب إدخال رموز حقن SQL مثل `' OR 1=1 --`: تأكد من رفضها فوراً في مرحلة التحقق من المعرف.

#### الخطوة 6: تعليق الحسابات وحظر Supabase Auth
- [ ] من لوحة الموظفين، اختر موظفاً واضغط على زر "تعليق الحساب".
- [ ] حاول تسجيل الدخول بحسابه المعلق: يجب أن يرفض النظام الدخول مباشرة.
- [ ] تأكد من استدعاء `ban_duration: '876000h'` في Supabase Auth لمنع إصدار أي Refresh Tokens له.
- [ ] حاول تعليق أو حذف حساب مدير النظام الرئيسي `marwan-desouky`: تأكد من حمايته البرمجية المطلقة ورفض العملية.
- [ ] أعد تنشيط الموظف وتأكد من رفع الحظر وعودة قدرته على تسجيل الدخول.

#### الخطوة 7: التحقق من معالجات الأمان البرمجية (Phase A Security Cleanup)
- [ ] التأكد من حذف نقاط النهاية التجريبية الخطرة (`test-auth` و `reset-password-force`) من الدالة السحابية `admin-users`.
- [ ] استدعاء إجراء استعراض المستخدمين في `admin-users` والتأكد من تطبيق التصفح بالصفحات (`page` و `per_page` مع سقف أقصى 100 سجل) لمنع استنزاف موارد الخادم.
- [ ] فحص استجابات API للتأكد من تعقيم بيانات المستخدمين وحذف أي حقول حساسة مثل `password` أو `user_metadata.password` من كائنات المستخدم المسترجعة.
- [ ] التحقق من منع الحساب القديم `marwandesouqhi@gmail.com` من تسجيل الدخول أو إضافته إلى قاعدة البيانات المحلية.

#### الخطوة 8: التحقق من مسار تفعيل الموظفين عبر الروابط (Phase B Employee Onboarding Flow)
- [ ] من لوحة إدارة المستخدمين، إرسال دعوة لموظف جديد والحصول على رابط التفعيل الآمن:
  `http://localhost:5173/auth?tab=activate&token=<SECURE_INVITATION_TOKEN>`
- [ ] فتح الرابط في متصفح جديد (أو نافذة خفية):
  - [ ] التحقق من استدعاء دالة التحقق من التوكن `validate_invitation_token`.
  - [ ] التأكد من عرض تفاصيل الدعوة (الاسم، البريد الإلكتروني، القسم، الصلاحية) بصورة للقراءة فقط مع قفل الحقول.
  - [ ] إدخال كلمة مرور جديدة مطابقة لمعايير الأمان (8 أحرف على الأقل، حرف كبير، رقم).
  - [ ] الضغط على "تفعيل الحساب وتعيين كلمة المرور".
  - [ ] التحقق من استدعاء الإجراء الذري `complete_employee_activation` وتحويل حالة الدعوة إلى `accepted` والحساب إلى `active`.
  - [ ] التحقق من تسجيل دخول الموظف تلقائياً وتوجيهه إلى الصفحة الرئيسية مع عرض إشعار الترحيب بنجاح.
  - [ ] محاولة استخدام نفس رابط التفعيل مرة ثانية: التأكد من رفض النظام للعملية وإظهار رسالة تفيد بأن الرابط مستخدم أو منتهي الصلاحية.

#### الخطوة 9: التحقق من نظام التصميم وتجربة المستخدم (Phase C UI/UX Verification)
- [ ] **نظام المتغيرات اللونية (Design Tokens):**
  - [ ] فتح تبديل النمط (Light / Dark Theme) والتأكد من توافق كافة الألوان ووضوح النصوص بنسبة تباين WCAG AA (لا تقل عن 4.5:1 للنصوص و 3:1 للعناصر التفاعلية).
  - [ ] التحقق من ألوان المؤشرات والرسوم البيانية (`--chart-1` إلى `--chart-5`) في لوحات تحليلات المشتريات والعهدة.
- [ ] **التجاوب والشاشات المختلفة (Responsive Breakpoints):**
  - [ ] تجربة النظام على شاشات الجوال (`max-width: 640px`): طي القائمة الجانبية في شريط علوي، تحويل الجداول إلى كروت تمرير أفقي سلس `.table-responsive`.
  - [ ] تجربة النظام على الأجهزة اللوحية (`max-width: 980px`): تجاوب شبكة المؤشرات `.kpi-grid` وشاشات المقارنة.
  - [ ] تجربة الشاشات المكتبية والواسعة (`1200px` وما فوق): ثبات التوزيع بدون أي تشويه بصري.
- [ ] **إذن الصرف والطباعة الحكومية (Official Permit Modal):**
  - [ ] فتح نافذة "إصدار وطباعة إذن صرف عهدة رسمي".
  - [ ] التأكد من أن عناصر التحكم والتعديل تظهر بنمط التصميم الحديث الموحد على الشاشة، وتختفي تماماً عند الطباعة (`no-print`).
  - [ ] الضغط على زر "طباعة الإذن الآن": التأكد من خروج مستند A4 بالأبيض والأسود مع الترويسة والأختام والتوقيعات الرسمية دون أي تأثير من ثيم النظام أو ألوان الشاشة.

### 4. إجراءات التراجع في حالات الطوارئ

إذا واجهت أي تعارض غير متوقع في بيئة التشغيل، يتوفر لكل ملف هجرة ملف تراجع نظيف ومستقل في مجلد `supabase/rollbacks/`:

```bash
# للتراجع عن تفعيل الموظفين (Phase B):
supabase db execute -f supabase/rollbacks/20261018150000_employee_onboarding_activation.rollback.sql

# للتراجع عن Session C:
supabase db execute -f supabase/rollbacks/20261017150000_approval_delegation_code_registry_and_rls.rollback.sql

# للتراجع عن Session B:
supabase db execute -f supabase/rollbacks/20261017140000_telegram_bot_hardening_and_email_verification.rollback.sql

# للتراجع عن Session A:
supabase db execute -f supabase/rollbacks/20261017130000_lockdown_privileged_functions_and_bootstrap.rollback.sql
```
