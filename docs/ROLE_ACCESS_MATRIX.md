# صلاحيات المستخدمين

تم تطبيق القواعد على الواجهة، وظائف Supabase وسياسات RLS، وليس على إظهار الأزرار فقط.

| الدور | نطاق العرض والطباعة وتصدير التقارير | الإضافة | التعديل والحذف |
|---|---|---|---|
| `system_admin` مدير النظام الرئيسي | جميع الأقسام وصفحات النظام والمستخدمين | الكل | الكل |
| `admin` أدمن عام | جميع أقسام العمل؛ بدون صفحات إدارة النظام والمستخدمين | لا | لا |
| `warehouse_admin` أدمن قسم المخازن | المخازن فقط | لا | لا |
| `procurement_admin` أدمن قسم المشتريات | المشتريات فقط | لا | لا |
| `warehouse_employee` موظف مخازن | المخازن فقط | في المخازن | لا |
| `procurement_employee` موظف مشتريات | المشتريات فقط | في المشتريات | لا |

الأدوار القديمة `warehouse_staff` و`editor` تتبع صلاحيات موظف المخازن، و`purchasing_staff` يتبع موظف المشتريات. احتُفظ بمعرّفاتها لتوافق الحسابات الموجودة. دور `viewer` القديم يظل للقراءة، ولا يفتح صفحات الإدارة.

الصلاحيات الإضافية القديمة، مثل `manage_records`، لا تتجاوز حدود الدور الجديد. إجراءات اعتماد الطلبات وتغيير حالتها واختيار العرض الفائز مقتصرة على مدير النظام؛ يستطيع موظف المشتريات إنشاء أمر جديد عبر RPC بعد اعتماد الطلب والعرض.

مصدر التفويض في قاعدة البيانات هو الدور الحالي للحساب النشط في `app_users`. لا يُقبل توكن قديم لدور أعلى لتجاوز تغيير الدور أو إيقاف الحساب. حساب مدير النظام الحالي يظل بصلاحياته الكاملة. بيانات الحساب الشخصية والتفعيل واستعادة كلمة المرور تظل خدمات ذاتية؛ إدارة حسابات الآخرين مقصورة على مدير النظام.

إضافة فاتورة مشتريات أو صرف/نقل مخزني تستخدم عملية خادم محددة تحفظ الحركة وتحدّث الرصيد ذريًا. لا تُمنح صلاحية UPDATE عامة للموظف لتحديث الرصيد الناتج. إعادة إرسال الحركة لا تضاعف الكمية، ولا تكشف بصمة فاتورة من القسم الآخر.

كاش بيانات العمل والإشعارات وقوائم المستخدمين يُمسح عند تبديل الحساب أو الدور. تُرفض كذلك استجابة API قديمة إذا وصلت بعد تبديل الحساب، حتى لا تُخزّن بيانات الحساب السابق في كاش الحساب الجديد.

التقارير المالية وبنود الميزانية القديمة التي تجمع بيانات القسمين ولم يكن لها نطاق موثّق تظل ظاهرة للأدمن العام ومدير النظام فقط. السجلات الجديدة التي ينشئها الموظف تُنسب إلى قسمه تلقائيًا في الخادم؛ لا يستطيع اختيار قسم آخر في الطلب المباشر.

## التحقق

- `npx vitest run tests/unit --maxWorkers=1`: مرّ 404 اختبارًا في 44 ملفًا.
- الفحوص المحددة بعد إضافة عزل الاستجابات: مرّ 117 اختبارًا، منها منع استجابة قديمة من الوصول إلى كاش حساب جديد.
- `npm run test:roles:db`: 160 تحققًا على PostgreSQL معزول، عبر 10 أدوار؛ يتضمن إنشاء السجلات، منع التعديل والحذف، منع تزوير الاعتماد، نقل المخزون، تعطيل الحساب والتوكن القديم.
- اختبارات وظائف Edge تُشغّل المعالج الفعلي بهويات وعميل قاعدة بيانات وهميين، وتتحقق من منع العمليات قبل أي وصول لبيانات حسابات الآخرين.
- فحوص مباشرة على قاعدة البيانات المنشورة نجحت باستخدام هويات اختبار داخل معاملات تم إلغاؤها بـROLLBACK؛ لم تبقَ حسابات اختبار.
- نجح `npm run build` وفحص TypeScript. نجح lint مع تحذيرات موجودة في المشروع.

بعد التحديث، يُفضّل تسجيل الخروج والدخول لتحديث بيانات الدور في الواجهة. قاعدة البيانات لا تعتمد على استمرار صلاحيات الدور القديم داخل التوكن.
