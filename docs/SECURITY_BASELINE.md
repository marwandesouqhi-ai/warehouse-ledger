## 1. ملخص وضع الأمان الحالي (Current Security Posture)

| المحور | الوضع الحالي في خط الأساس (Baseline) | المخاطر المترتبة | الإجراء المستهدف في خطة الترقية |
| :--- | :--- | :--- | :--- |
| **مصادقة المستخدمين (Auth)** | حسابات محلية مخزنة في `localStorage` (`warehouse-ledger-local-users`) ومرآة `app_users`، مع تخزين كلمات المرور بصيغة نصية. | كشف كلمات المرور في حال الوصول إلى محطة العمل أو التخزين المحلي. | الاعتماد على **Supabase Auth** بإيميلات اصطناعية `<username>@warehouse.local` مع تشفير الهش التلقائي وتفعيل `must_change_password`. |
| **مصدر قرارات الصلاحية** | كان يعتمد في بعض المواضع السابقة على `user_metadata` التي يستطيع المستخدم تعديلها ذاتياً من العميل. | إمكانية تصعيد الصلاحيات (Privilege Escalation). | إلغاء أي اعتماد على `user_metadata`، والاعتماد حصرياً على **`app_metadata`** المشفرة بالـ JWT والتي لا يكتبها إلا الـ Service Role. |
| **قواعد أمان الجداول (RLS)** | تمكين سياسات RLS مع شروط واسعة `USING (true)` لـ `anon` في بعض هجرات المزامنة لتسهيل التطوير. | إمكانية الوصول المباشر لقاعدة البيانات عبر المفتاح العام دون المرور بمنطق الواجهة. | استبدالها بسياسات مشددة تعتمد على `app_metadata` عبر دوال `SECURITY DEFINER`، مع إعداد سكريبت تراجع (Rollback). |
| **سجلات التدقيق (Audit Logs)** | السماح بالإدراج المفتوح مع وجود إيميل محدد في بعض السياسات القديمة وغياب منع التعديل/الحذف التام. | إمكانية تزوير هوية كاتب السجل أو مسح السجلات. | ربط هوية الكاتب بالـ JWT (`auth.jwt()->>'email'`)، ومنع `UPDATE`/`DELETE` بتريجر ثابت غير قابل للكسر، وإزالة أي إيميلات شخصية. |
| **الملفات المتتبعة في Git** | ملفات مجلد `supabase/.temp/` متتبعة حالياً في مستودع Git (`git ls-files`). | تتبع ملفات إدارة داخلية للمشروع. | توثيق أوامر إزالتها من تتبع Git وإضافتها لـ `.gitignore`. |
| **نطاق موظف المشتريات** | موظف المشتريات يرى صفحات المشتريات، ولكن لم يكن هناك قيد RLS على مستوى الصفوف وقصر وصوله للمشتريات فقط. | وصول محتمل لحركات المخازن الأخرى. | قصر الوصول في الواجهة والـ RLS على حركات `purchase` لجميع موظفي المشتريات (`purchasesScope = 'all'`) ومنع رؤية العهد والمنصرف. |

## 2. مصفوفة الصلاحيات المستهدفة عبر `app_metadata`

```
JWT app_metadata:
{
  "role": "system_admin" | "admin" | "warehouse_staff" | "purchasing_staff" | "editor" | "viewer",
  "permissions": ["view_audit", "view_settings", "manage_records"],
  "must_change_password": boolean
}
```

- **marwan-desouky:** السيستم أدمن الوحيد الحاصل على جميع الصلاحيات الشاملة.
- **admin (أدمن عادي):** إدارة العمليات دون إعدادات المؤسسة أو سجلات التدقيق أو إدارة المستخدمين إلا بصلاحيات إضافية صريحة.
- **warehouse_staff:** حركات العهدة والمنصرف والتحويل بين الفروع وقراءة المشتريات.
- **purchasing_staff:** حركات المشتريات كاملة (الخاصة به وبغيره) واستيرادها والتقارير الخاصة بها، مع الحجب التام لصفحات العهدة والمنصرف والأرصدة العامة.
- **editor / viewer:** للتوافق الرجعي فقط.

## 3. وضع التوافق المزدوج (Dual-Mode Authentication)

- **Legacy Mode (`VITE_AUTH_MODE=legacy`):** الوضع الافتراضي لضمان عدم قفل أي مستخدم حالي حتى التحقق التام.
- **Secure Mode (`VITE_AUTH_MODE=secure`):** وضع التحويل والإنتاج الآمن بعد نقل المستخدمين إلى Supabase Auth وتطبيق قيود RLS.
